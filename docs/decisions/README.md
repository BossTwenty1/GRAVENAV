# Architecture Decision Records

## What is an ADR?

An Architecture Decision Record (ADR) captures an important technical or architectural decision, the context behind it, the alternatives considered, and its consequences. ADRs provide a durable record of why the project works a particular way.

## When to create an ADR

Create an ADR when a decision has meaningful, long-lived impact on architecture, technology, data, security, deployment, operations, or maintainability. Create it before implementation when practical, and update its status if the decision is superseded.

Do not create an ADR for routine implementation details or decisions that are still exploratory and unapproved.

## Naming format

Use a zero-padded sequence number and a short kebab-case title:

```text
0001-use-example-technology.md
```

## Suggested ADR structure

```markdown
# Title

## Status

## Context

## Decision

## Consequences

## Alternatives Considered
```
